# Zoho Billing MCP Skill

Portable OpenClaw/Agent Skill for finding Zoho Billing MCP setup Actions and selecting an endpoint. Based on the [Zoho Books MCP skill](https://github.com/sprintberlin/openclaw-zoho-books-mcp-skill), but Billing Actions are taken from a separate Billing setup UI export.

## What is included

- **518 Billing Actions**: exact setup value (`key`), display name (`name`), and description in `references/actions.jsonl`.
- Two least-privilege starting profiles and two read-only task selections in `references/profiles.json`.
- Local lookup, validation, and JSON export importer; a local-only endpoint configuration checker.
- Credential-free tests and GitHub Actions CI. Python standard library only.

The export is a snapshot, not a live server inventory. The source contains no MCP tool argument/response schemas, runtime names, endpoint or organization data. **No Billing MCP server was tested for this release.** Always inspect your own server and the exact live tool schema before use. Do not assume that an Action is enabled, available in your region/edition, or has any specific runtime name or parameters.

## Quick start

```bash
python3 scripts/lookup_actions.py --profiles
python3 scripts/lookup_actions.py --profile billing-readonly --names-only
python3 scripts/lookup_actions.py --search subscription
python3 scripts/lookup_actions.py --action 'List all Invoices'
python3 scripts/lookup_actions.py --task invoice-inspection --names-only
python3 scripts/lookup_actions.py --validate
python3 -m unittest discover -s tests -v
```

Action profiles select **setup Action values**, not accounts. `--names-only` prints the exact setup display names for copying into the setup UI. Profiles are suggestions: enable only the Actions actually needed, even within `billing-readonly`. The broader `billing-operations` profile can change data and is never the default; writes need explicit authorization.

## Setup and authentication

Create a Zoho Billing MCP server in the Zoho MCP portal for your region and select only needed Actions. Use a **Zoho Connection configured on the server** for Zoho authorization and required scopes; the client should not supply a Zoho OAuth access token as an action argument or invent an `Authorization` schema. The MCP endpoint/client authentication may be separately credential-bearing; use the endpoint generated by your server. Do not hardcode a region or assume all servers have the same auth mode; follow the actual server's instructions.

Set `ZOHO_BILLING_MCP_URL` securely (prefer secret-manager injection) or configure a named account profile as described in [MULTI_ACCOUNT.md](references/MULTI_ACCOUNT.md). Then validate selection **without connecting or displaying the URL**:

```bash
python3 scripts/check_endpoint.py
python3 scripts/check_endpoint.py --profile sample
```

To inspect your server, use an MCP client such as `mcporter` and its current documentation. Inspect the live tool list and exact schema before calling. `mcporter list "$ZOHO_BILLING_MCP_URL"` may expose the URL in a process listing or shell debugging; do not paste output containing credentials or sensitive information. Server-side Zoho authorization is via Connection; do not add a guessed client-side authorization header.

For a different account or organization, explicitly select its endpoint/profile, verify the target using an appropriate live read, and never fall back to another account on error. Parameters, organization selection, pagination and runtime tool names must come from the live schema, not this catalog.

## Security and billing safety

- Treat the endpoint, URL files, connection credentials, and customer/financial records as secrets. Do not commit or log them. A URL passed on the command line can appear in process lists and shell history.
- The default suggested selection is read-only, but even reads can expose sensitive data. Avoid unnecessary fields and records.
- Payment collection, refunds, credits, invoice void/write-off, cancellation, destructive/bulk and outgoing communications require explicit authorization; leave disabled until needed. Creating/updating subscriptions or invoices may have financial effects too.
- Before a write, verify target account, organization, IDs, currency, tax, amounts and duplicates; afterward verify the intended result. Stop if uncertain.
- The catalog and profiles grant no permissions and cannot enforce least privilege. Enforce it on the server Connection and Action selection.
